# Day 9 — DeepSeek Chat App: Development, Icon Design & Rename (2026-08-04)

**Objective:** Develop a ChatGPT-style chat app for the ATK-IMX6U using the
**DeepSeek V4 Flash** model via an **OpenCode Go** API key — from requirements
discussion, through Qt5 app development and deployment debugging, to the
app-icon design iterations and the final rename from `chatgpt` to `DeepSeek`.

---

## 1. App Requirements

ChatGPT-official-style UI (message panel on top-right,
input box on bottom-right) with these behaviors:

1. Reading an API key from `.env` when the app starts.
2. An on-screen keyboard (English input) appears when the input box is tapped.
3. Pressing Enter sends the user message (shown right) and the model reply
   appears (shown left).
4. New messages keep appending at the bottom; older ones move up.
5. A vertical scroll bar appears when messages overflow the message panel.
6. A vertical scroll bar on the input box when text overflows it.

---

## 2. Tech Stack Decisions

### 2.1 DeepSeek V4 Flash via OpenCode Go (API key)

- **API key source:** an **OpenCode Go** subscription key (`sk-...`), *not* a
  DeepSeek-official key.
- **Endpoint:** `https://opencode.ai/zen/go/v1/chat/completions`
  (OpenAI-compatible format, confirmed from `opencode.ai/docs/go` — DeepSeek
  V4 Flash → model id `deepseek-v4-flash`).
- **Implementation:** `Authorization: Bearer <key>` header; the key is read
  from `/opt/ui/src/apps/.env` (`API_KEY=...`) at app launch.
- **Note:** the correct endpoint/model were verified from the OpenCode docs
  (DeepSeek V4 Flash row: endpoint + `@ai-sdk/openai-compatible`).

### 2.2 Keyboard: Qt VirtualKeyboard (option B)

- Chosen over USB keyboard / custom QML keyboard.
- Required adding `qt5virtualkeyboard` to the buildroot packages.

### 2.3 Buildroot additions

```
BR2_PACKAGE_OPENSSL=y            # HTTPS for the API
BR2_PACKAGE_QT5VIRTUALKEYBOARD=y # on-screen keyboard
```

## 3. Buildroot Environment (2 pitfalls)

| Issue | Fix |
|-------|-----|
| VirtualKeyboard **Plugins module missing** — `InputPanel` unavailable, `module "QtQuick.VirtualKeyboard.Plugins" is not installed` | buildroot does not build input-method plugins by default; editing the package mk with `CONFIG+=plugin-pinyin` was **ineffective** — `config.pri` shows the trigger is `lang-zh_CN` (or `lang-all`) → `CONFIG+=lang-zh_CN` + `qt5virtualkeyboard-dirclean` |
| qt5base did not rebuild when OpenSSL was added → **`Protocol "https" is unknown`** | new dependencies do not trigger a re-configure → `make qt5base-dirclean` + full rebuild (QtNetwork now carries SSL, loaded via dlopen) |

Note: an overlay-vs-target rsync failure (`could not make way for new regular
file: opt/ui/src/apps/chatgpt`) broke `target-finalize` — cleaned the stale
directory in `output/target` and re-ran make.

---

## 4. App Development & Deployment (3 pitfalls)

| Issue | Fix |
|-------|-----|
| App freezes/black when launched from the launcher (QML `InputPanel` load failure) | `QtQuick.VirtualKeyboard.Plugins` is registered **dynamically by the QPA plugin** — only loaded when `QT_IM_MODULE=qtvirtualkeyboard` → `qputenv("QT_IM_MODULE", "qtvirtualkeyboard")` in `main.cpp` before creating `QGuiApplication` |
| `Permission denied` when the launcher starts the app (exit 126) | **Deployment layout error**: the binary was placed in a subdirectory
  (`/opt/ui/src/apps/chatgpt/chatgpt`) but the launcher executes
  `/opt/ui/src/apps/<name>` → the binary must sit **directly** in
  `/opt/ui/src/apps/`; `.env` is then read from `applicationDirPath()`
  (`/opt/ui/src/apps/.env`) |
| `SSL handshake failed` | After enabling OpenSSL + rebuilding qt5base, the board's `openssl s_client` verified the server fine (Verification: OK) — the failure was in Qt's SSL layer → force `QSsl::TlsV1_2OrLater` on the request + ignore SSL errors (embedded device, acceptable) |

---

## 5. UI Fixes (3 issues)

| Issue | Fix |
|-------|-----|
| Multi-turn messages **overlap** | delegate height relied on `bubble.height` (a `Rectangle` has no implicit height → 0) → bind delegate/bubble height to `textContent.implicitHeight` |
| New messages don't auto-scroll to bottom | `onCountChanged: positionViewAtEnd()` runs before layout → use `Qt.callLater(chatList.positionViewAtEnd)` |
| No floating return ball / tap does nothing / dialog turned white | the app's `main.qml` (overwritten from template) had dropped the `Client` component → re-added `Client { programmerName: ... }`; the **white dialog** was the Client's full-screen `AppMainBody` → made it transparent; set `Client { z: 999 }` so the floating ball receives taps |

## 6. App Icon Design (iterations)

- Started from the DeepSeek SVG logo → converted to 120x120 PNG with
  `rsvg-convert` (installed `librsvg2-bin`).
- Iterations: white rounded-square background appeared transparent →
  discovered the logo's `scale(0.234375)` filled the whole canvas (white
  barely visible) → shrunk the logo; then the real root cause: **the launcher
  cfg pointed to `deepseek.png`, but the new images were deployed to
  `chatgpt.png`** — the fix was to **always overwrite only the board's
  `/opt/ui/src/appicons/deepseek.png`**.
- Final icon: white rounded-rectangle + blue DeepSeek logo, composed with
  System.Drawing (white rounded path + logo overlay) — corners transparent.

---

## 7. Rename: chatgpt → DeepSeek

- Renamed the project directory and source files
  (`chatgpt.pro` → `DeepSeek.pro`, `chatgptclient.*` → `DeepSeekclient.*`),
  updated references in `.pro` and `#include`.
- **Missed rename:** the QML `Client { programmerName: "chatgpt" }` stayed
  `"chatgpt"` while the binary/cfg became `DeepSeek` — this name mismatch
  broke the launcher's app tracking (floating-ball return left the screen
  partially uncleared). Fix: `programmerName: "DeepSeek"`.
- Deployed the new `DeepSeek` binary, removed the old `chatgpt` binary, and
  updated the launcher cfg program name to `DeepSeek`.

## 9. Key Takeaways

1. **VirtualKeyboard needs its QPA plugin loaded** — set
   `QT_IM_MODULE=qtvirtualkeyboard` (in the app, before `QGuiApplication`).
2. **buildroot input-method plugins** are enabled by language config
   (`lang-zh_CN`), not `plugin-<name>`.
3. **New dependencies don't re-configure qt5base** — `qt5base-dirclean` +
   rebuild is required (e.g. OpenSSL for HTTPS).
4. **Launcher executes `/opt/ui/src/apps/<name>`** — binaries must sit
   directly there; resources (`.env`) live next to the binary.
5. **SSL debugging**: verify with `openssl s_client` first; if the system
   TLS is fine, look at the Qt layer (TLS version, CA, ignore-errors).
6. **QML delegate height**: never rely on a `Rectangle`'s implicit height —
   bind to the text's `implicitHeight`.
7. **`Qt.callLater`** for scroll-to-end after model changes (layout timing).
8. **The launcher's Client component** provides the floating return ball —
   keep it; its `AppMainBody` may need to be transparent.
9. **Icon path truth**: the cfg decides which icon file is shown — verify
   `deepseek.png` vs `chatgpt.png`; keep one authoritative path.
10. **Rename thoroughly**: source files, references, and **QML
    `programmerName`** must all match — a name mismatch breaks launcher
    app tracking.
