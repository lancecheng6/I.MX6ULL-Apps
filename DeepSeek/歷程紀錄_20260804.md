# Day 9 — DeepSeek 聊天 App：開發、圖示設計與改名（2026-08-04）

**目標：** 為 ATK-IMX6U 開發 ChatGPT 風格的聊天 App，使用 **OpenCode Go 提供的 DeepSeek V4 Flash API key**——從需求討論、Qt5 App 開發與部署除錯，到 App 圖示設計的多次迭代，最後把專案從 `chatgpt` 改名為 `DeepSeek`。

---

## 1. App 需求

ChatGPT 官網風格介面（右上對話框、右下輸入框）與以下行為：

1. 啟動時從 `.env` 讀取 API key。
2. 點擊輸入框後出現螢幕鍵盤（英文輸入）。
3. 按下 Enter 送出我方訊息（顯示在右側），模型回覆顯示在左側。
4. 新訊息持續加到最下方，舊訊息向上移動。
5. 訊息超過對話框上邊界時出現垂直捲軸。
6. 輸入文字超過輸入框下邊界時出現垂直捲軸。

---

## 2. 技術棧決策

### 2.1 DeepSeek V4 Flash（OpenCode Go 的 API key）

- **API key 來源：** **OpenCode Go** 訂閱的 key（`sk-...`），**不是** DeepSeek 官方 key。
- **Endpoint：** `https://opencode.ai/zen/go/v1/chat/completions`（OpenAI 相容格式；由 `opencode.ai/docs/go` 確認：DeepSeek V4 Flash → model id `deepseek-v4-flash`）。
- **實作：** `Authorization: Bearer <key>` 標頭；key 在啟動時從 `/opt/ui/src/apps/.env`（`API_KEY=...`）讀取。
- **備註：** 正確的 endpoint/model 是研讀 OpenCode 文件取得的（DeepSeek V4 Flash 列：endpoint + `@ai-sdk/openai-compatible`）。

### 2.2 鍵盤：Qt VirtualKeyboard（方案 B）

- 選擇螢幕鍵盤（相對於 USB 鍵盤 / 自製 QML 鍵盤）。
- 需要 buildroot 加 `qt5virtualkeyboard` 套件。

### 2.3 buildroot 增補

```
BR2_PACKAGE_OPENSSL=y            # API 的 HTTPS
BR2_PACKAGE_QT5VIRTUALKEYBOARD=y # 螢幕鍵盤
```

## 3. Buildroot 環境（2 個坑）

| 問題 | 解法 |
|-------|-----|
| VirtualKeyboard **Plugins 模組缺失**——`InputPanel` 無法載入、`module "QtQuick.VirtualKeyboard.Plugins" is not installed` | buildroot 預設不編輸入法插件；改 mk 加 `CONFIG+=plugin-pinyin` **無效**——`config.pri` 顯示觸發條件是 `lang-zh_CN`（或 `lang-all`）→ 改 `CONFIG+=lang-zh_CN` + `qt5virtualkeyboard-dirclean` |
| 加 OpenSSL 後 qt5base 沒重編 → **`Protocol "https" is unknown`** | 新增依賴不會觸發重新 configure → `make qt5base-dirclean` 完整重編（QtNetwork 現在內含 SSL，運行時 dlopen 載入）|

註：overlay 與 target 的 rsync 衝突（`could not make way for new regular file: opt/ui/src/apps/chatgpt`）使 `target-finalize` 失敗——清除 `output/target` 內的舊目錄後重跑 make。

## 4. App 開發與部署（3 個坑）

| 問題 | 解法 |
|-------|-----|
| 從啟動器點擊後 App 凍結/黑畫面（QML `InputPanel` 載入失敗）| `QtQuick.VirtualKeyboard.Plugins` 是由 **QPA 插件動態註冊**——只在 `QT_IM_MODULE=qtvirtualkeyboard` 時載入 → 在 `main.cpp` 建立 `QGuiApplication` 前 `qputenv("QT_IM_MODULE", "qtvirtualkeyboard")` |
| 啟動器啟動 App 時 `Permission denied`（exit 126）| **部署結構錯誤**：二進位放在子目錄（`/opt/ui/src/apps/chatgpt/chatgpt`），但啟動器執行 `/opt/ui/src/apps/<名稱>` → 二進位必須**直接放在 `/opt/ui/src/apps/`**；`.env` 則由 `applicationDirPath()` 決定（`/opt/ui/src/apps/.env`）|
| `SSL handshake failed` | 開 OpenSSL + 重編 qt5base 後，板子 `openssl s_client` 驗證伺服器正常（Verification: OK）——問題在 Qt 的 SSL 層 → 請求強制 `QSsl::TlsV1_2OrLater` + 忽略 SSL 錯誤（嵌入式設備，可接受）|

## 5. UI 修正（3 個問題）

| 問題 | 解法 |
|-------|-----|
| 多輪對話文字**重疊** | delegate 高度依賴 `bubble.height`（`Rectangle` 無隱式高度 → 0）→ 改綁定 `textContent.implicitHeight` |
| 新訊息不會自動捲到底 | `onCountChanged: positionViewAtEnd()` 在佈局前執行 → 改用 `Qt.callLater(chatList.positionViewAtEnd)` |
| 無懸浮球 / 點擊無效 / 對話框變白 | 覆寫 main.qml 時把 `Client` 元件刪掉了 → 加回 `Client { programmerName: ... }`；**白色對話框** = Client 的全屏 `AppMainBody` → 改透明；`Client { z: 999 }` 讓懸浮球接收點擊 |

## 6. App 圖示設計（多次迭代）

- 從 DeepSeek 的 SVG logo 開始 → 安裝 `librsvg2-bin` → 用 `rsvg-convert` 轉成 120x120 PNG。
- 迭代過程：白色圓角底看起來透明 → 發現 logo 的 `scale(0.234375)` 填滿整個畫布（白底幾乎看不見）→ 縮小 logo；接著找到**真正的根因**：啟動器 cfg 指向 `deepseek.png`，但新圖都部署到 `chatgpt.png` → 確立「**只覆寫板子的 `/opt/ui/src/appicons/deepseek.png`**」流程。
- 最終圖示：白色圓角方形 + 藍色 DeepSeek logo，用 System.Drawing 合成（白色圓角路徑 + logo 疊加）——角落透明。

## 7. 改名：chatgpt → DeepSeek

- 改名專案目錄與源碼檔（`chatgpt.pro` → `DeepSeek.pro`、`chatgptclient.*` → `DeepSeekclient.*`），更新 `.pro` 與 `#include` 引用。
- **漏改一處：** QML 的 `Client { programmerName: "chatgpt" }` 仍是 `"chatgpt"`，但二進位/cfg 已變 `DeepSeek`——名稱不一致破壞了啟動器的 App 追蹤（懸浮球返回後畫面無法完整刷新）。修正：`programmerName: "DeepSeek"`。
- 部署新的 `DeepSeek` 二進位、移除舊的 `chatgpt` 二進位、更新啟動器 cfg 的程式名為 `DeepSeek`。

## 8. 最終狀態

- **DeepSeek** App 在 ATK-IMX6U 上運作：ChatGPT 風格 UI、虛擬鍵盤、多輪對話（DeepSeek V4 Flash / OpenCode Go）、懸浮返回按鈕、自動捲動、DeepSeek 圖示。
- 端到端驗證：啟動器 → App → 輸入 → API 回覆 → 返回桌面完整刷新。

## 9. 重點總結

1. **VirtualKeyboard 需要載入它的 QPA 插件**——設定 `QT_IM_MODULE=qtvirtualkeyboard`（在 App 內、`QGuiApplication` 之前）。
2. **buildroot 的輸入法插件**由語言配置觸發（`lang-zh_CN`），不是 `plugin-<名稱>`。
3. **新增依賴不會讓 qt5base 重新 configure**——需要 `qt5base-dirclean` + 重編（例如 OpenSSL 的 HTTPS）。
4. **啟動器執行 `/opt/ui/src/apps/<名稱>`**——二進位必須直接放那；資源（`.env`）與二進位同目錄。
5. **SSL 除錯**：先用 `openssl s_client` 驗證；系統 TLS 沒問題就往 Qt 層查（TLS 版本、CA、忽略錯誤）。
6. **QML delegate 高度**：不要依賴 `Rectangle` 的隱式高度——綁定文字的 `implicitHeight`。
7. **`Qt.callLater`** 用於 model 改變後的捲到底（佈局時序）。
8. **啟動器的 Client 元件**提供懸浮返回球——要保留；它的 `AppMainBody` 可能需要設透明。
9. **圖示路徑的真相**：cfg 決定顯示哪個圖示檔——確認 `deepseek.png` vs `chatgpt.png`；保持單一權威路徑。
10. **改名要徹底**：源碼檔、引用、以及 **QML 的 `programmerName`** 必須一致——名稱不一致會破壞啟動器的 App 追蹤。
