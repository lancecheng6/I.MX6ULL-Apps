# Day 1 — SIEMENS HMI：S7-200 Smart PLC 觸控面板（2026-08-23）

**目標：** 為 ATK-IMX6U 開發一個輕量級 PLC 觸控面板，使用 Qt5/QML + snap7 直接與 S7-200 Smart SR30 通訊。

⚠️ **注意：** 由於 i.MX6ULL 開發板的 CPU 效能（Cortex-A7 @792MHz）與記憶體（512MB DDR3L）限制，本專案無法設計成完整的 SCADA 系統。與 PC 端的 C# WinForms SCADA 相比，做了以下取捨：

- ❌ 無歷史數據查詢（無 SQLite/資料庫）
- ❌ 無用戶管理系統
- ❌ 無複雜圖表/趨勢線
- ❌ 無動畫圖表（無 GPU 加速，linuxfb 無法運作 QtGraphicalEffects）
- ✅ 即時感測器數據顯示（200ms 輪詢）
- ✅ 泵浦/閥門開關控制（V 脈衝 + Q 直接輸出，實體驗證繼電器動作）
- ✅ SystemUI 整合（懸浮返回按鈕、桌面圖示）
- ✅ 斷線時凍結數據（不歸零）
- ✅ 未連線時控制項禁用（灰色外觀）

---

## 1. App 需求

1. 透過 S7 協議與 S7-200 Smart PLC 通訊
2. 顯示 8 個感測器數值（進水壓力、出水壓力、進水溫度、出水溫度、鍋爐壓力、鍋爐液位、鍋爐溫度、儲水罐液位）
3. 5 個開關控制泵浦/閥門（V100.x 脈衝 + Q 直接輸出）
4. Connect/Disconnect 按鈕
5. System Status 顯示（RUNNING/STOPPED）
6. 斷線時保留最後數值
7. 未連線時控制項禁用（灰色）
8. 指示燈邏輯：停止=綠燈，動作=紅燈

---

## 2. 技術棧決策

| 技術 | 選擇 | 原因 |
|------|------|------|
| UI 框架 | Qt5/QML (Quick Controls 2) | 板子已有 Qt5 Buildroot 環境，QML 觸控友好 |
| PLC 通訊 | snap7 v1.4.2 | 開源 C 函式庫，支援 S7 協議，可編譯為靜態庫 |
| 執行緒模型 | QThread + QTimer(200ms) | 避免 UI 卡頓 |
| 通訊保護 | QMutex | 防止多執行緒競爭 snap7 socket |
| 桌面整合 | SystemUI Client | 懸浮返回按鈕 + App 生命週期管理 |
| 建置工具 | Buildroot GCC 12.3.0 | ARMv7 交叉編譯 |

---

## 3. 問題與解法

| # | 問題 | 解法 |
|---|------|------|
| 1 | Client.qml 覆蓋全螢幕吃掉觸控 | AppMainBody 設 z:0，Client 設 z:99 + anchors.fill |
| 2 | Worker/Main thread 同時讀寫 snap7 socket | QMutex 保護所有 snap7 操作 |
| 3 | QML Repeater JS 閉包失效（fn 函式不觸發） | 改用 switch-case 直接呼叫 C++ 方法 |
| 4 | Switch checked 綁定覆蓋使用者切換 | 使用 onToggled + modelData.state 綁定 |
| 5 | 指示燈顏色邏輯不對（綠色=動作） | 改為：停止=綠燈(#2ecc71)，動作=紅燈(#e74c3c) |
| 6 | Disconnect 後 System 仍顯示 RUNNING | 加入 plc.connected 雙重判斷 |
| 7 | Disconnect 後感測器歸零 | disconnectPlc() 不清除 m_data |
| 8 | 未連線時控制項仍可操作 | GridLayout 加 enabled: plc.connected |
| 9 | 桌面圖示名稱顯示為「Heating」 | 修改 apk1.cfg 的顯示名稱為「SIEMENS HMI」 |
| 10 | PLC IP 跨子網需每次加路由 | 改 PLC IP 為 192.168.1.200（同 eth0 子網） |
| 11 | PLC 梯形圖只映射 V 旗標不驅動 Q 輸出 | 同時寫 V 脈衝 + 直接寫 Q 輸出區（已驗證繼電器動作） |
| 12 | WiFi SSH 不穩定（PC 板子互 ping 失敗） | PC 被手機熱點搶走 WiFi → 重連 BELL357 |

## 6. 重點總結

1. **i.MX6ULL 無 GPU**——無法使用 QtGraphicalEffects，QML 動畫需節制。
2. **snap7 靜態編譯**——用 buildroot 工具鏈編 `libsnap7.a`，避免動態庫依賴。
3. **QML↔C++ 橋接**——Q_INVOKABLE + setContextProperty 是唯一可靠的通訊方式。
4. **Repeater JS 閉包不可靠**——改用 switch-case 直接呼叫 C++ 方法。
5. **QMutex 是必要的**——多執行緒讀寫同一個 TCP socket 會導致崩潰。
6. **SystemUI Client 的 z 軸**——z:99 確保浮動按鈕在最上層，z:0 確保內容可觸控。
7. **PLC IP 同子網**——避免路由腳本，開機即通。
8. **斷線數據凍結**——disconnectPlc() 不清除 m_data，UI 保留最後數值。
9. **指示燈邏輯**——工業標準：紅色=動作，綠色=停止。
10. **開發板性能限制**——完整 SCADA 需要更高階硬體（GPU、更多 RAM、更高 CPU）。
