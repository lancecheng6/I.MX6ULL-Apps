# Day 1 — SIEMENS HMI: S7-200 Smart PLC Touch Panel (2026-08-23)

**Goal:** Develop a lightweight PLC touch panel for the ATK-IMX6U board, using Qt5/QML + snap7 to communicate directly with S7-200 Smart SR30.

⚠️ **Note:** Due to the CPU performance (Cortex-A7 @792MHz) and memory (512MB DDR3L) limitations of the i.MX6ULL board, this project cannot be designed as a full SCADA system. Compared to the PC-side C# WinForms SCADA, the following trade-offs were made:

- ❌ No historical data query (no SQLite/database)
- ❌ No user management system
- ❌ No complex charts/trend lines
- ❌ No animated gauges (no GPU acceleration; linuxfb cannot run QtGraphicalEffects)
- ✅ Real-time sensor data display (200ms polling)
- ✅ Pump/valve switch control (V pulse + Q direct output, relay verified)
- ✅ SystemUI integration (floating back button, desktop icon)
- ✅ Data freeze on disconnect (no reset to zero)
- ✅ Controls disabled when disconnected (grayed out appearance)

---

## 1. App Requirements

1. Communicate with S7-200 Smart PLC via S7 protocol
2. Display 8 sensor values (inlet/outlet pressure, inlet/outlet temperature, boiler pressure, boiler level, boiler temperature, tank level)
3. 5 switch controls for pumps/valves (V100.x pulse + Q direct output)
4. Connect/Disconnect buttons
5. System Status display (RUNNING/STOPPED)
6. Preserve last values on disconnect
7. Disable controls when disconnected (gray appearance)
8. Indicator light logic: idle=green, active=red

---

## 2. Technology Stack

| Technology | Choice | Reason |
|------------|--------|--------|
| UI Framework | Qt5/QML (Quick Controls 2) | Board has Qt5 Buildroot environment; QML is touch-friendly |
| PLC Communication | snap7 v1.4.2 | Open-source C library supporting S7 protocol; can be built as static library |
| Threading Model | QThread + QTimer (200ms) | Prevents UI blocking |
| Communication Safety | QMutex | Prevents multi-thread socket contention on snap7 |
| Desktop Integration | SystemUI Client | Floating back button + app lifecycle management |
| Build Toolchain | Buildroot GCC 12.3.0 | ARMv7 cross-compilation |

## 3. Issues and Solutions

| # | Issue | Solution |
|---|-------|----------|
| 1 | Client.qml covers full screen, hijacking touch events | AppMainBody z:0, Client z:99 + anchors.fill |
| 2 | Worker/Main threads read/write snap7 socket simultaneously | QMutex protects all snap7 operations |
| 3 | QML Repeater JS closure failure (fn function not triggering) | Switch to switch-case calling C++ methods directly |
| 4 | Switch checked binding overrides user toggle | Use onToggled + modelData.state binding |
| 5 | Indicator light color logic inverted (green=active) | Changed to: idle=green(#2ecc71), active=red(#e74c3c) |
| 6 | System still shows RUNNING after Disconnect | Added plc.connected double-check |
| 7 | Sensor values reset to zero on Disconnect | disconnectPlc() does not clear m_data |
| 8 | Controls still operable when disconnected | GridLayout added enabled: plc.connected |
| 9 | Desktop icon name shows "Heating" | Updated apk1.cfg display name to "SIEMENS HMI" |
| 10 | PLC IP on different subnet requires manual routing | Changed PLC IP to 192.168.1.200 (same subnet as eth0) |
| 11 | PLC ladder only maps V flags, not Q outputs | Write V pulse + direct Q output simultaneously (relay verified) |
| 12 | WiFi SSH unstable (PC-board ping failure) | PC WiFi taken over by mobile hotspot -> reconnect BELL357 |

## 6. Key Takeaways

1. **i.MX6ULL has no GPU** — QtGraphicalEffects cannot be used; QML animations must be conservative.
2. **snap7 static build** — Use buildroot toolchain to compile `libsnap7.a`, avoiding dynamic library dependencies.
3. **QML<->C++ bridge** — Q_INVOKABLE + setContextProperty is the only reliable communication method.
4. **Repeater JS closures are unreliable** — Switch to switch-case calling C++ methods directly.
5. **QMutex is mandatory** — Concurrent read/write on the same TCP socket causes crashes.
6. **SystemUI Client z-axis** — z:99 keeps floating button on top, z:0 ensures content is touchable.
7. **PLC same subnet** — Eliminates routing scripts; instant connection on boot.
8. **Disconnect data freeze** — disconnectPlc() does not clear m_data; UI preserves last values.
9. **Indicator light convention** — Industrial standard: red=active, green=idle.
10. **Board performance limitations** — Full SCADA requires higher-grade hardware (GPU, more RAM, higher CPU).
